- 汇报日期：2026 年 9 月 9 日
- 项目仓库：[numpy1314/tg-rcore-tutorial](https://github.com/numpy1314/tg-rcore-tutorial)
- 操作教程：[完整使用与演示教程](course-recording.md)
- 阶段定位：已实现学生本地的实验过程采集、实时查看、日志落盘和提交快照；尚未建设教师端集中服务。

## 一、建设目标与当前产物

本项目面向操作系统课程的教学辅助，帮助学生和助教回看实验过程、定位失败命令及理解 AI 辅助操作。过程记录用于教学服务，不自动生成分数，也不替代教师的最终评价。

当前产物已集成到真实 rCore 实验仓库中。学生只需运行根目录的 `course.py`，配套插件和辅助脚本放在 `.course-monitor/` 隐藏目录中，日志保存在同一仓库的 `.ai/` 中。

这是“一个使用入口 + 仓库内配套文件”的交付方式。入口负责配置和启动，实际文件采集由 VS Code 插件完成，AI 操作由专用调用入口记录，Git Hook 负责提交前导出快照。

## 二、已实现功能

| 功能 | 当前实现 | 使用方式与结果 |
|---|---|---|
| 一键配置与启动 | 定位脚本所在仓库，安装随仓库分发的插件，配置 Git Hook，打开实验与日志 | `python3 course.py` |
| 文件操作记录 | 记录项目内文件打开、关闭、修改、保存、新建、重命名、删除及时间信息 | 在 VS Code 中操作实验文件后自动生成事件 |
| 终端命令记录 | 记录支持 Shell Integration 的 VS Code 集成终端命令开始、结束、退出码等信息 | 在 VS Code 内新建终端并运行命令 |
| 任务事件记录 | 记录 VS Code Tasks 的开始、结束等事件 | 使用 VS Code 任务运行流程 |
| 实时日志查看 | Windows 提供独立日志窗口，可查看事件列表和单条详情；Linux/macOS 在终端持续显示日志 | `python3 course.py logs` |
| 日志自动保存 | 以 JSONL 文件保存事件，每行一条记录；关闭查看窗口不会删除文件 | 查看 `.ai/events/` |
| 真实 Codex 调用记录 | 通过专用入口调用 Codex CLI，记录 Prompt、会话、实际命令结果及文件操作事件 | `python3 course.py codex`，默认只读 |
| Codex 修改文件模式 | 允许本次调用在工作区内修改文件，并记录可解析的最终操作事件 | `python3 course.py codex --allow-edits` |
| 手动导出提交快照 | 对事件再次进行规则脱敏，按暂存区中已有事件 ID 去重后导出 | `python3 course.py export`，输出到 `.ai/submissions/` |
| Git 提交前导出 | 正常提交时运行 Hook，导出并暂存增量快照 | 使用正常 Git 提交流程；不自动推送 |
| 状态查询 | 显示记录开关、Hook 路径、日志位置、日志和快照文件数量 | `python3 course.py status` |
| 暂停和恢复记录 | 保留已有日志，通过项目配置控制采集 | 修改 `config.json` 的 `enabled`，再重载 VS Code |
| 采集范围与脱敏 | 排除仓库外路径、日志目录和部分敏感文件；对已识别的令牌、密码参数等内容进行替换 | 采集与导出过程中执行规则处理 |
| 容器接入配置 | 提供 Dev Container 配置、容器内 Hook 初始化和插件安装入口 | 按使用教程的容器章节配置 |

文件修改事件记录“发生过修改”，不记录逐行源码差异。短时间内的连续编辑可能合并，不按每次按键生成事件。

## 三、数据保存与提交流程

```text
学生在 VS Code 操作实验文件 / 使用课程 Codex 入口
                         ↓
                采集事件并进行规则脱敏
                         ↓
                .ai/events/*.jsonl
                    ↙          ↘
             实时日志查看器    导出脚本 / Git Hook
                                   ↓
                         .ai/submissions/*.jsonl
                                   ↓
                          正常 Git 提交与推送
```

| 位置 | 内容 | 是否默认随代码提交 |
|---|---|---|
| `course.py` | 学生使用入口 | 是 |
| `.course-monitor/` | 插件、查看器、采集与导出脚本 | 是，排除缓存和本机运行时 |
| `.ai/events/` | 已按采集规则处理的本地事件日志 | 否 |
| `.ai/submissions/` | 用于提交的增量事件快照 | 是，通过正常提交流程纳入 |
| `.ai/ide/` | 本机工作区配置、查看器状态等 | 否 |

当前日常日志格式为 JSONL。此前 SQLite Demo 中的 `rewind.db` 不作为当前入口的日志存储依据。

手动导出不会自动暂存、提交或上传。去重依据是 Git 暂存区中的已有快照；若反复手动导出但未暂存上次快照，相同事件可能再次被导出。正常 Hook 流程会导出并暂存快照。

## 四、现场演示方案

### 1. 打开真实实验仓库

在已具备 Python、Git 和 VS Code 的电脑上执行：

```sh
git clone https://github.com/numpy1314/tg-rcore-tutorial.git
cd tg-rcore-tutorial
python3 course.py
```

确认工作区受信任，将实验窗口和日志窗口并排放置。Windows 终端采集推荐使用 PowerShell 7。

### 2. 演示文件与命令记录

1. 打开 `tg-rcore-tutorial-ch1/src/main.rs`。
2. 添加一行 `// course demo` 并保存。
3. 在 VS Code 集成终端运行 `git status`。
4. 在日志窗口观察文件打开、修改、保存和命令事件。
5. 打开 `.ai/events/` 中最近更新的文件，确认同样的事件已经保存。
6. 删除演示注释并保存，恢复实验文件内容。

### 3. 演示 AI 交互记录

在 Codex CLI 已安装、登录且网络可用的前提下运行：

```sh
python3 course.py codex
```

输入：“请阅读 tg-rcore-tutorial-ch1/src/main.rs，用中文简要说明启动流程，不要修改文件。”

观察终端返回结果，并在日志窗口中查看 Prompt、会话和实际产生的操作事件。没有发生的文件修改不会产生文件修改事件。

### 4. 演示作业快照

执行 `python3 course.py export`，查看 `.ai/submissions/` 下生成的文件，说明该快照可以进入正常的作业提交流程。此步骤本身不上传文件。

## 七、当前边界与后续工作

目前工具运行在学生本地，实时窗口也是学生本地的查看器。没有教师端集中看板、自动日志上传服务、自动评分或可靠的人类/AI 全量行为判定。

普通文件事件无法单独证明由人还是 AI 操作。明确的 AI 操作来源于课程专用入口；普通桌面聊天、扩展聊天和外部终端不会自动成为这条采集链路的一部分。

本地日志和 Hook 由学生环境管理，可以被修改、关闭或绕过，不能作为不可篡改的考核证据。现阶段应服务于教学辅助和实验排障。

后续建议按以下顺序推进：

1. 在实际课程环境中统一验证插件、终端与容器配置，并明确采集告知和使用范围。
2. 接入课程实际使用的其他 AI 客户端，明确是否需要保存 AI 最终回答。
3. 建设日志接收服务与教师查看界面，定义提交失败重试和学生/实验身份关联。
4. 制定日志访问权限、保留期限与删除规则，再评估是否需要完整性校验。

本阶段已经形成可演示、可保存、可随正常 Git 流程提交的本地工具，为后续集中服务提供了基础。
